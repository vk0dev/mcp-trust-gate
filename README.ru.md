# @vk0/mcp-trust-gate

Предустановочный trust-гейт для MCP-серверов — детерминированный вердикт GO/REVIEW/BLOCK с доказательствами, до того как вы что-либо установите.

## Зачем

MCP-серверы получают реальный доступ: к файловой системе, браузеру, учётным данным, инфраструктуре. `npm install` не расскажет, что сервер сможет *сделать*, когда агент начнёт вызывать его тулы, — маркетинговый README обычно тоже. Ответ нужен **до** первого запуска сервера, а не после инцидента.

Используйте, когда пользователь спрашивает:
- «Безопасно ли ставить этот MCP-сервер?»
- «К чему на самом деле имеет доступ `@some/mcp-package`?»
- «Проверь MCP-серверы в моём `.mcp.json` перед новой сессией.»
- «Одобрять ли MCP-конфиг, который добавил коллега или агент?»
- «Изменилось ли поведение этого MCP-сервера с момента последнего одобрения?»

`mcp-trust-gate` отвечает детерминированным вердиктом — `GO`, `REVIEW` или `BLOCK` — подкреплённым доказательствами, а не ощущениями.

## Установка

### Claude Code
```bash
claude mcp add mcp-trust-gate -- npx -y @vk0/mcp-trust-gate
```

### Claude Desktop
Добавьте в `claude_desktop_config.json`:
```json
{
  "mcpServers": {
    "mcp-trust-gate": {
      "command": "npx",
      "args": ["-y", "@vk0/mcp-trust-gate"]
    }
  }
}
```

### Cursor
Добавьте в `.cursor/mcp.json`:
```json
{

    }
  }

```

### Windsurf

```json
{
  "mcpServers": {
    "mcp-trust-gate": {
      "command": "npx",

    }
  }

```

### CLI (автономно, без MCP-клиента)
```bash
npx @vk0/mcp-trust-gate @playwright/mcp --card
```

## Тулы

### `evaluate_install_gate`
**Вход:** `package_name` (строка) — имя npm-пакета MCP-сервера, например `@playwright/mcp` или `mcp-remote`.
**Выход:** вердикт (`GO`/`REVIEW`/`BLOCK`), сводка, 9 отдельных проверок с доказательствами, рекомендуемые действия и fingerprint текущего trust-состояния с детекцией дрейфа относительно прошлой оценки.
**Когда использовать:** перед установкой или включением любого npm-based MCP-сервера.

### `scan_config`
**Вход:** `config_path` (строка) — путь к файлу `.mcp.json` или `claude_desktop_config.json`.
**Выход:** батч-сводка с вердиктом по каждому серверу и итогами (`go`/`review`/`block`/`skipped`).
**Когда использовать:** для аудита всех MCP-серверов, уже настроенных в клиенте, — например перед новой сессией или при ревью чужого конфига.

## Пример диалога

> **Пользователь:** Безопасно ли ставить `@playwright/mcp`?
>
> **Агент:** *вызывает `evaluate_install_gate({ package_name: "@playwright/mcp" })`*
>
> **Агент:** REVIEW. Пакет чисто резолвится и прослеживается до `microsoft/playwright-mcp` с недавней активностью мейнтейнеров, но он заявляет автоматизацию браузера — перед включением уточните границу системы (какие сайты, какой профиль браузера).

## Как это работает

```
имя npm-пакета
      │
      ▼
┌─────────────────┐     ┌──────────────────────┐
│  реестр npm      │────▶│ 9 детерминированных  │
│  GitHub API      │     │ проверок (regex-     │
│  (кэш, ETag)     │     │ детекция сигналов)   │
└─────────────────┘     └──────────┬───────────┘
                                    ▼
                        вердикт: GO / REVIEW / BLOCK
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                                ▼
          fingerprint сохраняется            доказательства + причины +
          ~/.mcp-trust-gate/                 рекомендуемые действия
          fingerprints/<pkg>.json            возвращаются агенту
                    │
                    ▼
          сравнение со следующей
          оценкой → обнаружен дрейф?
```

Проверки идут по метаданным реестра npm и, если удаётся разрешить публичный GitHub-репозиторий, по метаданным репозитория (архивный статус, последний push). Ничего не исполняется — это статическая оценка метаданных, не песочница и не рантайм-сканер.

## FAQ

**Делает ли он сетевые запросы?**
Да. `evaluate_install_gate` и `scan_config` запрашивают реестр npm (`registry.npmjs.org`) и, когда из метаданных пакета удаётся разрешить GitHub-репозиторий, GitHub REST API (`api.github.com`). Ответы кэшируются в памяти на 5 минут, к GitHub идут условные (ETag) запросы для снижения нагрузки на rate-limit.

**Нужен ли API-ключ?**
Нет. Оба API опрашиваются без аутентификации. Неаутентифицированные вызовы GitHub ограничены жёстче — при достижении лимита проверки, зависящие от метаданных репозитория, деградируют мягко, а не роняют оценку.

**Насколько точен вердикт?**
Проверки — детерминированная regex-детекция сигналов по метаданным npm-пакета (описание, ключевые слова, имена bin, README-смежные поля), не рантайм- и не код-аудит. Трактуйте `GO` как «в метаданных нет очевидных красных флагов», а не «формально доказана безопасность». Вердикты `REVIEW` и `BLOCK` включают конкретные доказательства-триггеры, чтобы вы могли судить сами.

**Что с GitHub-only или не-npm MCP-серверами?**
V1 оценивает только опубликованные в npm цели. `scan_config` пропускает серверы, запускаемые не через `npx`/имя npm-пакета, и помечает их `SKIPPED`, а не гадает.

**Где хранятся данные fingerprint?**
Локально, в `~/.mcp-trust-gate/fingerprints/<package-name>.json`. Никуда не отправляются. Каждый вызов `evaluate_install_gate` сравнивает с последним сохранённым fingerprint и сообщает `driftDetected`, если изменились домен доступа, способность к мутациям, требование секретов или сигнал персистентности.

## Ограничения

- V1 оценивает только MCP-серверы, опубликованные в npm с резолвящейся записью на `registry.npmjs.org`.
- `scan_config` парсит только форматы `.mcp.json` и `claude_desktop_config.json`; специфичные форматы Cursor/Windsurf/Cline пока не поддержаны.
- Проверки — статические эвристики по метаданным, не рантайм-песочница, не код-аудит и не сканер уязвимостей зависимостей.
- Неаутентифицированные вызовы GitHub API подчиняются публичным rate-limit GitHub.
